① Configurable rule engine

Policy is data, not code

  • Every threshold & list moved into config/rules.json
  • rules/engine.py loads & validates it on startup
  • Agents read a RuleEngine — no hard-coded constants
  • Money stays Decimal (values are strings)

Change a threshold or a sanctions list without touching Python, then re-run.

{
  "high_value_amount": "10000",
  "off_hours_start": 0, "off_hours_end": 6,
  "ctr_threshold": "10000",
  "critical_risk_threshold": 70,
  "iso_4217_whitelist": ["USD","EUR","GBP","…"],
  "sanctioned_countries": [],
  "sanctioned_accounts": []
}

config/rules.json — one edit changes the whole pipeline

② REST API gateway

Submit & retrieve over HTTP

$ curl -X POST localhost:8100/transactions -d '{
    "transaction_id":"T100", "amount":"25000.00", "currency":"USD",
    "source_account":"ACC-1001", "transaction_type":"wire_transfer",
    "timestamp":"2026-03-16T09:00:00Z", "metadata":{"country":"US"} }'

→ 201 Created
  { "transaction_id": "T100",
    "status": "approved",
    "result": { "source_account": "ACC-****",     # PII masked
                "risk_score": 50,
                "compliance_flags": ["CTR"] } }

A transaction submitted over HTTP is scored, screened, decided, and stored — no transaction file involved.

③ One-command demo

./demo.sh — zero manual steps

  • Ensures the venv + installs deps
  • Starts the API, waits for /health
  • Submits a spread of sample transactions
  • Prints each result + the summary
  • trap shuts the server down on exit — nothing left running
$ ./demo.sh
▶ starting API on :8100 … ✓ up
── POST high-value wire   → approved (CTR)
── POST cross-border      → approved (EDD, flagged)
── POST bad currency XYZ  → rejected
✅ 4 submitted → 3 approved, 1 rejected
▶ stopping API …
