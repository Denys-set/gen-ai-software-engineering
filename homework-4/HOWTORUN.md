# HOWTORUN — Homework 4

Everything runs from the `homework-4/` directory.

---

## 1. Prerequisites

- **Node.js** ≥ 18 (uses built-in `crypto.timingSafeEqual`, modern Express). Check: `node -v`.
- **Claude Code CLI** on your PATH and authenticated — required only for `npm run pipeline`
  (the app and tests do not need it). Check: `claude --version`. If missing, install Claude Code
  and sign in first.

Install dependencies:

```bash
cd homework-4
npm install
```

---

## 2. Run the app

```bash
npm start                 # -> Notes app listening on http://localhost:3000
```

Open <http://localhost:3000> for the Tailwind UI. API examples:

```bash
# list notes
curl -s http://localhost:3000/api/notes

# create a note
curl -s -X POST -H "Content-Type: application/json" \
  -d '{"title":"Buy milk","body":"2 litres"}' http://localhost:3000/api/notes

# get one note
curl -s http://localhost:3000/api/notes/1

# get an unknown note -> 404 (BUG-1 fixed)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/api/notes/999

# search (SECURITY-1 fixed: input is HTML-escaped)
curl -s "http://localhost:3000/api/notes/search?q=hello"

# delete requires the admin token from the environment (SECURITY-2 fixed)
ADMIN_TOKEN=changeme npm start          # start with a token set, in one shell
curl -s -X DELETE -H "x-admin-token: changeme" \
  -o /dev/null -w "%{http_code}\n" http://localhost:3000/api/notes/2   # -> 204
```

> `DELETE` authorizes against `process.env.ADMIN_TOKEN`. If it is unset, the token is empty and
> **all deletes are rejected (401)** — the endpoint fails closed. Set `ADMIN_TOKEN` before
> `npm start` to enable deletes.

## 3. Run the tests

```bash
npm test
```

Expected: **10 passed** — `tests/notes.test.js` (4 baseline) + `tests/notes.fixed.test.js`
(6 regression tests generated by the Unit Test Generator, one group per fixed defect).

---

## 4. Run the whole pipeline (one command)

```bash
npm run pipeline
```

This executes `scripts/run-pipeline.sh`, which `cd`s into `homework-4/` and calls Claude Code
headless once per stage, in order. Each stage writes into `context/bugs/001/`:

| # | Stage (model) | Writes |
|---|---------------|--------|
| 1 | Bug Researcher (`sonnet`) | `research/codebase-research.md` |
| 2 | Research Verifier (`opus`), loads `research-quality-measurement` | `research/verified-research.md` |
| 3 | Bug Planner (`opus`) | `implementation-plan.md` |
| 4 | Bug Fixer (`sonnet`) | applies the plan, runs tests, `fix-summary.md` |
| 5 | Security Verifier (`opus`) | `security-report.md` |
| 6 | Unit Test Generator (`sonnet`), loads `unit-tests-FIRST` | `tests/notes.fixed.test.js`, `test-report.md` |

After stage 6 the runner runs `npm test` and prints where the outputs were written.

### Permissions

The headless stages need to run a few Bash commands (`npm test`, `npm ls`, …). Two options:

- **Default (recommended):** `homework-4/.claude/settings.json` allow-lists exactly those
  commands, so the run is non-interactive without a blanket bypass. Just run `npm run pipeline`.
- **Escape hatch:** skip all permission checks for the run:

  ```bash
  PIPELINE_BYPASS=1 npm run pipeline
  ```

  This uses `--permission-mode bypassPermissions`. Broader — use only if you trust the tree.

> The runner fails fast with a clear message if the `claude` CLI is not installed.

## 5. Reproduce the before → after

The seeded defects and their post-fix behavior (start the app first). Because the pipeline already
applied the fixes to source, the commands below show the **fixed** ("after") behavior:

| Defect | Command | After (fixed) |
|--------|---------|---------------|
| BUG-1 | `curl -s -o /dev/null -w "%{http_code}\n" localhost:3000/api/notes/999` | `404` |
| BUG-2 | delete id 2, then create a note | new id is `3`, never `2` |
| SECURITY-1 | `curl -s "localhost:3000/api/notes/search?q=<script>alert(1)</script>"` | reflects escaped `&lt;script&gt;…`, no raw tag |
| SECURITY-2 | `curl -s -X DELETE localhost:3000/api/notes/1 -w "%{http_code}\n"` (no token) | `401` |

To see the **before** ("buggy") state, check out the commit prior to the pipeline's fix commit,
or read the seeded symptoms in [`context/bugs/001/bug-context.md`](./context/bugs/001/bug-context.md).
